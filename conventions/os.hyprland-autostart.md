# Convention: Hyprland session startup (os.hyprland-autostart)

The systemd user transaction is a security-critical boot chain. The
`keystone-startup-lock.service` unit MUST complete before
`graphical-session.target`. The service launches the lock screen and requests
session termination if the lock surface fails to appear.

This convention originated in ks.systems/os when the `exec-once` list was
generated by Nix: a priority collision between `mkDefault` (priority 1000) and
`mkAfter` (priority 100) silently replaced the entire base exec-once list,
dropping the lock screen, D-Bus setup, polkit agent, and clipboard manager.
The list now lives in the dotfile template (`templates/hyprland/.config/hypr/
hyprland.conf`) and in each user's stowed copy — the failure mode changed
shape, but the invariant did not.

## Boot chain context

```
greetd → UWSM → WAYLAND_DISPLAY → keystone-startup-lock → graphical-session.target
```

The unit MUST require and start after `wayland-session-waitenv.service`. It
MUST be required by and ordered before `graphical-session.target`. If Hyprlock
does not present a lock surface, the script requests session termination and
returns failure. Systemd then blocks the graphical target transaction.

## Base list ownership

1. Home Manager owns the startup-lock unit and the persistent background
   services.
2. Lua configuration MUST NOT launch the startup lock or import the systemd
   environment.
3. The `template-startup-lock` check (`tests/default.nix`) enforces the unit
   dependency and ordering contract.

## Adding autostart commands

4. Persistent background processes MUST use systemd user services bound to
   `graphical-session.target`.
5. Personal one-shot startup actions MAY use `hl.on("hyprland.start", ...)` in
   `user.lua` or `host.lua`. They MUST NOT provide security-critical session
   wiring.
6. Nix modules MUST NOT generate compositor settings. Stowed Lua files remain
   the only live compositor configuration.

## Customizing the lock command

7. The lock gate is not a user-editable compositor setting. Changes to its
   command or ordering belong in the desktop Home Manager module.
